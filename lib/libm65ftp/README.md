# lib/libm65ftp — vendored MEGA65 FTP library

This directory is a copy of the MEGA65 FTP library from the upstream
[MEGA65/mega65-tools](https://github.com/MEGA65/mega65-tools) repository (the
`mega65_ftp` tool, GPL-3.0).

Unlike m65defrag's stripped ethernet-only copy, mega65fs vendors the *full*
library: the USB/serial transport, `filehost`, `diskman` and `bit2mcs` code
paths are all kept.  Only the interactive shell / `main()` entry point is
guarded out, and unused headers are omitted.

## What lives here

Copied verbatim from upstream (paths relative to the upstream repo root):

- `mega65_ftp.c` — the core MEGA65-FTP protocol (`src/tools/mega65_ftp.c`).
- `m65common.c`, `logging.c`, `filehost.c`, `filehost.h`, `diskman.c`,
  `diskman.h`, `bit2mcs.c` — shared helpers and support code (`src/tools/`).
- `etherload/etherload_common.c` — ETHLOAD bootstrap loader core
  (`src/tools/etherload/`).
- `include/` — public headers (`include/`): `dirtymock.h`, `etherload_common.h`,
  `fpgajtag.h`, `logging.h`, `m65common.h`.

Generated from upstream assembly sources (see *Regeneration* below):

- `etherload/ethlet_{dma_load,echo,all_done_basic2,all_done_basic65,all_done_jump}.c`
  — etherload support programs, byte arrays built from the corresponding
  `ethlet_*.a65` sources (`src/tools/etherload/`).  All five are vendored and
  built by the Makefile.
- The matching `etherload/ethlet_*_map.h` — symbol-offset headers generated
  from the assembler map files.

Not synced (pinned as checked in):

- `ftphelper.c` — the serial helper routine byte array.  Upstream generates it
  from `src/utilities/remotesd.c` via the cc65 cross-compiler
  (`bin2c remotesd.prg helperroutine ftphelper.c`), which needs a cc65 +
  mega65-libc toolchain, so it is not regenerated by the sync scripts.
- `ftphelper_eth.c` — the ethernet helper routine byte array.  Upstream
  generates it from `src/utilities/remotesd_eth.c` via the cc65 cross-compiler
  (`bin2c remotesd_eth.prg helperroutine_eth ftphelper_eth.c`), likewise not
  regenerated.

Local, not from upstream:

- `version.c` — a small local `version_string` ("custom-build"), standing in
  for upstream's `src/gitversion.sh`-generated `src/tools/version.c`.

Deliberately omitted (unused by this build):

- `etherload.c` — the standalone `etherload` tool entry point (the Makefile
  builds only the library sources above).
- `include/ascii.h`, `include/screen_shot.h` — referenced by no code in this
  build.

The local wrapper API (`m65ftp_*` read/write/stat/readdir/…) lives in
`src/m65ftp_lib.c` / `src/m65ftp_lib.h` and is **not** vendored — it is this
project's own code, kept separate so the vendored core can be refreshed
wholesale.

## Local deltas

Applied on top of upstream after every sync (see the sync scripts):

1. **`M65FTP_AS_LIB` guard** (`mega65_ftp.c`) — the interactive-shell and
   `main()` sections of `mega65_ftp.c` are wrapped in
   `#ifndef M65FTP_AS_LIB` / `#endif` so the file compiles as a library when
   `-DM65FTP_AS_LIB` is defined (`src/m65ftp_lib.c` textual-includes it).  The
   guard also relocates the now-unused `show_buf` buffer outside the guarded
   region.
2. **`d_mtime`** (`mega65_ftp.c`) — `struct m65dirent` gains a `d_mtime` field
   and `fat_readdir` fills it from the raw directory entry; `src/m65ftp_lib.c`
   uses it to report modification times.
3. **`find_free_cluster` rewrite** (`mega65_ftp.c`) — clamps `first_cluster`
   to ≥ 2 and searches forward, then wraps around from cluster 2 to
   `first_cluster - 1`, so free-cluster allocation finds gaps anywhere on the
   volume.
4. **`find_contiguous_clusters` guard** (`mega65_ftp.c`) — a
   `if (!start_cluster) return 0;` check after the `find_free_cluster` call,
   since the rewritten allocator returns 0 when the volume is full.

Keep the list in sync with the sync scripts' "re-apply the local deltas"
output.

## Regeneration

The `ethlet_*.c` / `ethlet_*_map.h` files are regenerated by the sync
script using the same pipeline as the upstream Makefile:

    ophis -4 --no-warn ethlet_<name>.a65 -l <name>.list -m <name>.map -o <name>.bin
    bin2c  <name>.bin  ethlet_<name>  ethlet_<name>.c
    map2h  <name>.map  ethlet_<name>  ethlet_<name>_map.h

The script also re-copies the verbatim files listed above:

- `scripts/sync-upstream.sh` — Linux (requires `git`, `cc`, `python3`).

- `ophis` is the Ophis cross-assembler (MEGA65 fork:
  <https://github.com/gardners/Ophis>); the script clones it automatically or
  honours `OPHIS_BIN`.
- `bin2c` and `map2h` are vendored in `scripts/` as verbatim copies of the
  upstream tools (`src/tools/bin2c.c`, `src/tools/map2h.c`); the script
  compiles them with the platform C compiler.

`scripts/bin2c.c` and `scripts/map2h.c` are GPL-3.0 upstream MEGA65 tools
code, kept verbatim.
